平面测距的基准是隔离悬空箱体与货车**保守碰撞矩形**的间距，不代表所有曲面/路沿都达到同样误差。货车车尾包络比名义视觉 bbox 额外包含 0.55 米，以覆盖实测碰撞体并避免自回波。

转角标定与验证使用不同控制值。独立验证控制为 ±0.4、±0.6、±0.85、±0.95，前进和倒车各一组；约 5 km/h、平地、3 米行程内逐帧比较四角位置。标定只匹配 European HGV 与构建 3b938d7；不推及全部速度/载荷/坡度，也不等于验证了全部 12 米预测范围。先前满舵倒车的短行程训练没有记作 3 米验收通过。

## 未全部通过的真实目标检查

现场共 38 个记录：35 个数值检查中 22 项通过、13 项未通过；另有 2 项蓝图不可用和 1 项需要图像复核。完整失败项保留在 field.json 与 summary.json，自动流程的 field 阶段返回码为 2，没有强制改成通过。

- Tesla 车辆四角的 12 个包围盒间距基准：差距约 0.38–0.41 米。曲面/碰撞表面与 bbox 角点不同，且有限雷达采样不保证命中最近表面。该差距不能被本次平面测试的约 12 cm 结果覆盖。
- 1 米路锥检查：相对包围盒基准约 0.20 米差距，超过 0.15 米阈值，未通过。
- 当前库没有可直接生成的 wall/curb 蓝图，真实路沿专项仍未完成；平面箱体是受控平面实验，不冒充所有真实墙体与路沿验证。
- BEV 与主视图截图已检查：布局无旧版大片空白，前/后切换正确，轨迹按地面投影显示；未给所有像素的重投影误差作全场景数值承诺。立体物体仍存在平面 IPM 拉伸。

因此本版本状态是**在线测量完成并有明确限制**，不是“全部环境验收通过”。

## 在线测试发现并修正的问题

1. 本机构建 get_matrix 旋转与 Transform.transform 不一致：改为前/右/上基向量矩阵，并增加旋转、逆变换回归测试。
2. 车尾碰撞体自回波：修正保守包络与雷达外侧安装位置，不用屏蔽某个距离段掩盖自车。
3. 120° 车角覆盖不足：保持四雷达，扩大为 170°、每个 12000 点/秒；超量程回波显式丢弃。
4. 多后轴大转角侧向滑移：独立数据标定曲率与侧向滑移，再以未参与训练的转角验证全程路径。
5. 参考射线起点/自车命中：排除零行程命中，避免错误的约 2 cm 参考距离。
6. 相机一帧延迟：雷达位置标记转换到图像采集位姿，当前数值保留当前雷达来源。
7. 初始下落显示为行驶速度：启动先稳定悬架，速度只计水平分量；地面高度改取车轮接地点。
8. 处理耗时过高：异步取完整帧组、低分辨率米制 BEV 计算后等比显示、向量化雷达处理和局部标签混合；最终 GUI 实测接近 20 FPS。

## 原始证据与复现

- `planar.json`：平面基准 24 项。
- `field.json`：现场目标、窄通道、平行靠近及普通转弯，包括所有失败项。
- `../live-session/steering-validated-path.json`：16 项独立转角的逐帧路径最大误差。
- `gui/telemetry.jsonl`：200 帧真实 GUI 时间戳、图像帧号、雷达状态。
- `views/forward/hud.png`、`views/turn_left/hud.png`、`views/turn_right/hud.png`、`views/reverse/hud.png`：真实 CARLA 静态方向视图，未用合成数据冒充。
- `execution.json`：自动流程命令、退出码和耗时。
- `unit-tests.log`：36 项回归测试输出。

在已启动的专用 CARLA 服务端上运行：

```bash
conda run --no-capture-output -n carla python tools/run_online_checks.py
conda run --no-capture-output -n carla python tools/validate_steering.py
```

普通 GUI 的 FPS 数据在关闭独立射线诊断时测量；开启 `--validate` 会增加额外耗时。全部测试 actors 已清理，CARLA 服务端保留运行供后续演示。
