# CARLA 远程驾驶辅助设计（已批准）

## 目标与已确认路线

在现有 Python、pygame、OpenCV 演示上，为操作 European HGV 的远程驾驶操作员提供四摄环视、前进/倒车视图切换、动态轨迹与周边障碍物净空提示。参考 `ref_pic/0–7.jpeg` 的信息组织方式，优先保证几何正确、信息可信和演示稳定。

用户已选择路线 A：雷达作为界面测距来源，CARLA 场景射线查询作为独立校验来源。本设计随后已获用户明确批准，业务代码实施已授权。

备选路线 B 是先完善射线测距与界面，再接雷达，能更早演示，但后续仍要重新验证传感器覆盖。A 更适合逐步迁移到远程驾驶平台，因此被选择。

## 范围与约束

- 保留指定车型 `vehicle.carlamotors.european_hgv` 和现有键盘控制入口；支持前进、倒车、静止打方向。
- 第一版定位于低速操控辅助。建议验收速度 0–10 km/h，不声称适用于高速动态预测。
- 不实现自动泊车、自动制动、路径规划、远程网络传输或真实硬件驱动。
- 不实现透明底盘、可旋转 3D 环视、额外轮毂相机及历史图像补全。
- 生产图像来自前后左右四路 RGB 相机；环视不能改用空中相机伪装拼接。
- 雷达是 CARLA `sensor.other.radar` 的仿真量测，不声称复现真实毫米波雷达全部电磁特性。
- 使用现有 `carla` Conda 环境；实施时核对实际客户端/服务器版本和蓝图属性，避免按最新版文档假定本机能力。
- 当前目录的 Git 元数据不可用；设计不要求初始化新仓库、提交或覆盖已有版本历史。

## 当前实现及待修正问题

主循环依次执行车辆控制、tick、相机取图、轨迹生成、射线查询、BEV 拼接和 HUD 绘制。

1. HUD 的 BEV 已采用 `_blit_square_centered`。1920×1080 时实际左面板约 936×958，与遗留的 620 像素布局参数不一致。不能直接沿用旧版本关于 cover 缩放的诊断。
2. 轨迹生成读取了后轴位置，却未完整用于最终 actor 坐标换算；保险杠起点被当作圆弧路程偏移，轨迹宽度取轮距而非车身宽度。需要以实际车辆几何和仿真行驶结果验证。
3. 相机各自取最新帧但不检查 frame 编号，不能保证四摄同帧。
4. 现有射线仅 24 条，只保留部分车辆类别，从车身外扩 0.35 米处开始计距；不能直接用作车身净空真值。
5. 配置存在左右方向约定不一致的注释和扇区命名，须统一并以左右独立障碍物场景检查。

源码静态发现不等于运行时根因已经全部复现；实施首先记录基线截图、帧编号与车辆几何，再逐项验证。

## 几何与轨迹

统一采用 CARLA actor 局部坐标：+X 向前、+Y 向右、+Z 向上。所有传感器外参、包围盒中心、车轮坐标、轨迹和 BEV 映射均以此为交换坐标。

运行时读取车辆包围盒、轴位置和转向参数，明确单位与局部/世界坐标语义，不假定 actor 原点就是后轴。货车双后轴采用低速等效后轴；选取方法由实施者结合物理参数和实车仿真轨迹决定并记录。转向正负号以实际左右转弯校验。

低速运动模型预测车辆姿态序列，再变换前后保险杠角点和车身轮廓，形成行进方向边界与车身扫掠区域。边界从当前保险杠角点起始，转弯时包含外侧扫掠和车尾外摆；不以轮迹代替车身占用范围。

相机叠加与 BEV 使用同一组几何数据。先在米制坐标中生成完整预测，再分别进行各视图的投影和裁剪，不能让 BEV 的显示范围截断主摄像头轨迹。近裁剪与画幅边界按线段处理，避免因端点在画幅外使整段消失。可见性受相机安装限制，不人为将线拖到画面底部。

第一版按局部平坦路面设计，并校正 actor 原点至地面的高度；坡道、路面起伏下的精确贴地轨迹不在首版承诺范围。距离标记只表示预测位置，不表示已确认可通行。

## 四摄环视与界面

四摄按 frame 编号配对，保留 timestamp 与外参信息；有界等待、有限缓存、明确超时。缺帧时保留上一完整组并标记过期，不把不同帧静默拼接。

先验证实际相机姿态、图像通道、曝光与自车遮挡，再调整地面投影、有效区域掩码和重叠融合。相机安装参数可以在四摄约束内调整。覆盖检查包括包围盒外 0.15–4 米的地面环带；超出视场、被遮挡或无法投影的区域显示为明确的不可见底纹，不能插值成有效画面。

维持参考图的信息结构：左侧约三分之一宽度为纵向环视，右上为行进方向主视图，右下为左右视图，顶部和底部显示必要车辆状态。比例为实施提案，以适应长货车及保留主视图空间。BEV 输出范围与面板纵横比共同设计，像素/米在两个轴上保持一致；不得非等比拉伸车身或以裁掉近障碍区域填满面板。

前进挡显示前视，倒挡显示后视，左右视图持续可见；静止时跟随所选挡位。转弯改变轨迹，首版不额外自动切换相机。支持清晰的前/后/左/右标签，后视是否镜像须统一其图像、叠加和标签规则并记录，默认使用传感器原始方向。

BEV 使用按真实比例绘制的货车示意、行进边界、近障碍分区色块及距离标签。去除干扰信息的过密圆环。第一版不增加声音报警。

地面投影无法正确重建高出地面的立体物体；这类物体可能拉伸或重影，原始相机视图和雷达距离提供补充判断，不宣称无失真 3D 重建。

## 雷达测距与状态

先部署前、后、左、右四个雷达，安装于车身外缘，基于运行时车身几何设置位置。视场、俯仰、量测密度和频率由可复现覆盖测试选择；不能把四个方向等同于全车身无盲区。若四雷达无法覆盖长车侧面或四角，报告覆盖缺口；可提出增加角部/侧面雷达作为后续修订，首版不得暗中增加传感器数量。

每个检测点由深度与角度还原为三维点，再使用量测时刻传感器位姿转换到车辆坐标。剔除自车、地面及明显不相关的高空回波，保留与车辆碰撞高度范围相关的障碍点。阈值须集中配置，并记录低路沿漏检等能力边界。

界面主距离定义为检测点到车辆包围盒在地面的投影矩形的最短水平距离，不是雷达斜距、actor 中心距离或完整障碍表面的保证距离。按车身最近边/角归属八个扇区，保留命中位置供定位提示。

每扇区保留最近有效点。允许短时稳态滤波以减少抖动，但新出现的更近目标立即更新，不因平均平滑延迟危险接近。雷达量测携带来源、frame、timestamp、有效性与新鲜度。

区分有效距离、当前无回波、超时和不可覆盖状态。无回波不显示为“安全”或伪造最大距离；短时保留的距离必须带过期标记，建议 0.2 秒开始标记、0.5 秒后取消数值，最终值由实施者依据实际 tick 验证。

距离初始配色沿用现有阈值：≤1 米近距、1–2 米中距、2–4 米远距；超过标签范围不显示近距数字。阈值代表演示提示等级，不是制动安全距离。数字建议 0.1 米分辨率，不用厘米显示制造未经验证的精度印象。

## 独立校验

生产测距接口与校验接口分离。射线查询只进入诊断日志、导出报告或明确标记的调试显示，不参与生产距离的补填与融合。

校验覆盖静态墙、车辆、行人、柱体及低障碍物；避免沿用旧版车辆类别白名单。射线采用沿车身边缘分布、必要的多高度采样，记录射线起点与命中点，防止自车命中和外扩起点导致净空偏差。

射线结果也是离散采样参考，不称作全场景精确真值。标准墙面及已知位置障碍物场景额外使用可计算几何净空作基准。报告雷达检测点净空与参考最近净空的差异、漏检和覆盖缺口，区别采样误差与换算错误。

## 代码组织与规范

沿用 core（生命周期与控制）、perception（拼接与测距）、visualization（显示）、utils（数学）的职责。补充类型明确的车辆几何、帧组、距离观测与诊断结果数据结构；传感器回调只接收和入队，主线程处理数据。

统一 BGR/RGB 边界、米/厘米/度/弧度单位与转向符号。公开接口标注类型和单位，参数集中管理；避免新魔法数字、宽泛异常吞噬和调试输出污染主界面。新增传感器必须具备正常/异常退出清理路径。

## 实施顺序与验收

1. 核对本机 CARLA 版本与启动方式，记录现状截图、车辆几何、相机外参和 frame 对齐情况。
2. 校正坐标和几何模型、建立针对性数学回归测试，再修复轨迹生成与投影。
3. 实现帧组同步与雷达生命周期、点坐标换算、净空、分区及有效性状态。
4. 实现独立校验与覆盖检查，确认雷达能力缺口。
5. 调整 BEV 有效掩码、亮度、融合及 HUD 布局，接入轨迹和距离提示。
6. 运行下列场景并导出截图、诊断数据、运行说明及已知限制。

验收包括：

- 前进/倒车直行与左右转弯：辅助线起点锚定正确保险杠，左右方向正确，主视图与 BEV 使用相同预测。
- 低速固定转角行驶：记录预测车身轮廓与实际车身位置；建议 3 米行程内对应边界误差不超过 0.3 米，未满足时不得宣称模型验收通过，应报告模型适用范围并修正。
- 四侧与四角障碍物：提示方位正确；已知平面目标且有有效回波时，净空计算误差目标 ≤0.15 米。检测覆盖与计算精度分别统计，不能排除漏检后声称全部通过。
- 墙面平行靠近、窄通道、车辆、行人、柱体、低路沿：记录漏检率、最差误差及未覆盖区域。低路沿等无法稳定检测的情况明确列为限制。
- 缺帧、无回波、传感器超时：不混帧、不将未知显示为安全、不悄悄借用校验距离。
- 环视对齐：平坦地面已知标记与 BEV 位置一致；主界面无因布局错误产生的大块闲置区域，真实不可见区域保留明确标识。
- 默认 20 Hz 仿真下测量实际 UI 帧率、等待时延与数据年龄，目标稳定达到约 20 FPS；性能不足时优先保持控制响应与状态正确，报告硬件和实测结果。
- 退出与异常路径：释放新增相机/雷达等 actor，恢复原世界设置。

上述数值为待用户批准的验收目标，未实测前不承诺性能或传感器精度。
